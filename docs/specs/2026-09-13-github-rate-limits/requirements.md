# GitHub API 用量修正

使用者在設計檢查後以「好，修正」授權修正已確認的限流風險。

範圍：GitHub 來源的重複讀取、首次大量讀取、文字批次提交、網頁背景檢查與提交前檢查。網頁與遠端 MCP 共用來源層的最佳化。

維持本機來源、瀏覽器草稿、Markdown 原文、帳號隔離、路徑與 symlink 保護、單次原子 commit，以及非強制分支更新。不得變更使用者的 notes 內容或本次無關的工作區修改。

案例：100 篇公開筆記首次載入不應逐篇消耗 100 次 REST 額度；重複讀取不下載不變內容；不同憑證不得共用私有內容；限流後等待上游指定時間；提交 100 篇文字只需建立一個 tree、一個 commit、更新一次 ref；舊 revision 必須在寫入前被拒絕。

不包含：commit、push、部署、增加 GitHub 額度、替使用者設定新憑證或分散式儲存服務。

未決問題：無。
