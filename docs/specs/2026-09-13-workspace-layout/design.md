# 共用版面設計

保留 Header 的全域導覽，將筆記操作移入內容標題列。WorkspaceChrome 提供共用側欄（唯一捲動邊界、固定頁尾）及 PageHeader（標題、說明、操作）。四頁使用同一側欄寬度及內容間距；文件編輯器保留獨立內文捲動，不把整個編輯器嵌入可捲動卡片。

資源管理沿用 AssetLibrary 的目錄、選取與忙碌狀態，透過 renderSidebar 提供導覽，避免複製狀態或使側欄在操作途中改變目錄。插入資源的對話框沿用內嵌模式。

設定段落以穩定錨點導覽，保留所有已掛載表單和未儲存輸入。Agent 僅改版面，不改自動儲存、切換文件與唯讀判斷，並適應同期 Agent System 工作。

版面樣式集中在 workspace.css，沿用主題色而減淡側欄底色與分隔線；手機保留現有的視窗高度與底部安全區規則。相較全面搬動資料狀態，這個界面把共用幾何集中管理，既有功能元件繼續負責本身操作。

清單與卡片共用 FolderLinks 呈現資料夾入口，保留路徑提示、筆記數量及原導覽回呼，避免在筆記表格放入不適用的狀態／修改時間欄位。提交狀態列改為配置內的底部列，保留提交及回收區行為，讓四頁內容都不被浮層遮住。

驗證介面：瀏覽器實際四頁、側欄捲動及所有標籤可達、主題與窄螢幕；專案 pnpm test、pnpm build 與適用既有瀏覽器案例。完成後向使用者展示可操作結果，詢問整體視覺是否符合其預期。
