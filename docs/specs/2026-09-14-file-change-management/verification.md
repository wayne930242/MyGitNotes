# 驗證紀錄：逐檔變更管理與 Agent 還原

日期：2026-09-14。範圍：`github-notes` 的 `core` 工作目錄；保留原有文件右側面板與 Select 修改。所有可變更資料的測試皆使用臨時 Git 倉庫，沒有操作真實 `trpg-notes/notes/**`。

## 發現與修正

- Agent 還原原先僅檢查可編輯狀態；未修改的 Agent 檔案也會顯示可還原。改為檢查目前檔案的 Git 變更、已提交版本及寫入狀態，後端再核對逐檔版本。還原與提交後重新整理狀態。
- 筆記直接連結的還原判斷使用未初始化的編輯項目。改為使用路由實際開啟的檔案路徑。
- 底部提交視窗缺乏逐檔管理。補上工作目錄／暫存區分組、逐檔差異、暫存／取消暫存及具名還原確認。本機使用真實 Git index；遠端僅標示本次提交選取，沿用遠端版本衝突保護。
- 還原確認曾可能被另一列沿用。先加入跨檔點擊重現測試並確認失敗，再改為只有確認按鈕能授權還原；切換檔案只更新待確認的目標。
- 舊的選取檔案提交流程可能夾帶其他已暫存檔案。改為限定明確檔案提交，測試確認其他 index 內容保留。
- 整合測試修正三個等待時序：操作前訂閱回應、等待變更清單載入、還原完成後等待編輯器解除唯讀。未以延長逾時掩蓋問題。

## 驗證項目

- `pnpm test`：44 個測試檔、225 項測試；涵蓋真實 Git 暫存快照、後續工作目錄修改、單檔還原隔離、備份、新檔取消暫存、過期版本、路徑與 HTTP 安全邊界。
- `pnpm build`：完整建置；保留既有 Vite 大型 chunk 警告，無編譯錯誤。
- `qa-change-management.mjs`：直接連結筆記還原、其他檔案不受影響、工作目錄／暫存差異、取消暫存、跨檔確認、新檔丟棄、指定提交及行動版邊界。
- `qa-shared-editors.mjs`：乾淨 Agent 檔案不可還原；儲存佇列、快速切檔、晚到回應與失敗保留草稿；單檔還原後停用；只提交 Agent 後停用，其他筆記保持未提交。
- `qa-working-notes.mjs`：遠端局部提交、失敗保留草稿、版本合併／衝突、行動版提交與儲存錯誤。
- `qa-keyboard-shortcuts.mjs`：動作面板、焦點恢復、編輯器導覽暫停、leader 搜尋、J/K 目錄。
- `qa-mobile.mjs`：320／390／430／820／1440 px、觸控手勢、側欄、還原、編輯器、資源與遠端操作。
- 人工檢視 `artifacts/qa/changes-desktop.png` 與 `changes-mobile.png`，使用真正的 GitHub Dark 主題；清單、差異、輸入框與操作列均在視窗內。

## 限制與交付狀態

- 衝突、符號連結及受保護的產品檔案不允許從管理介面變更，需使用倉庫工具處理。
- 本機還原前保留目前工作檔備份於 Git 目錄；不宣稱外部 Git 程序與此介面的操作具備跨程序交易隔離。
- 交付範圍包含本次逐檔變更管理與既有文件右側面板修正。Core 提交推送後，依安全更新流程同步 `trpg-notes`；以更新前後筆記／設定指紋、測試、建置與遠端提交比對作為交付證據。
