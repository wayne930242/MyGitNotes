# MyGitNotes 領域詞彙

## MyGitNotes 與儲存來源

MyGitNotes 是以 Git 保存的個人筆記與文件工作區。平台指 GitHub 或 GitLab；站台指平台所在的服務網址；儲存庫是筆記的來源。每個部署指定主儲存庫的平台、站台、儲存庫與分支；筆記本可以另外指定自己的筆記本儲存庫。一次寫入只落在一個儲存庫。GitLab.com 與自架 GitLab 使用相同的工作區操作。

### 用語

**主儲存庫**：部署設定指定的儲存庫，保存工作區設定。沒有指定儲存庫的筆記本，內容也放在這裡。避免稱為：預設 repo、home repo。

**筆記本儲存庫**：一個筆記本的內容所在的儲存庫。一個筆記本只屬於一個儲存庫；筆記本儲存庫只放工作區內容，沒有 `core`。避免稱為：外部 repo、子 repo。

**儲存庫 manifest**：每個儲存庫自己的 `.mygitnotes.yaml`，決定這個儲存庫的標題（標頭、筆記本切換器分組、Changes 與 Agents 頁顯示的名稱）、開啟時的預設筆記本，以及它的筆記本使用的偏好設定。沒有 manifest 的儲存庫以儲存庫名稱顯示。筆記本儲存庫提供哪些筆記本，目前仍由主儲存庫 manifest 的 `source` 決定。

## Core 與工作區分支

同一個儲存庫以兩條分支分開產品與內容。`core` 只放產品原始碼，工作區只從 upstream fast-forward 它；`main` 只放工作區內容，不再合併 `core`。兩者各自 checkout 在自己的 worktree，local server 從 core worktree 執行並編輯 main worktree。

### 用語

**Core**：產品原始碼所在的 `core` 分支與其 worktree。避免稱為：上游分支（upstream 指 remote）。

**工作區內容**：`main` 上的 `.mygitnotes.yaml`、筆記本根目錄、素材與工作區 Agent 設定。避免稱為：使用者分支。

**fork 模型工作區**：分離前建立、`main` 仍帶著產品程式碼的舊工作區；以 `convert-workspace` 轉換一次。

**轉換**：以一個 commit 移除 fork 模型 `main` 上的產品路徑，使它只放工作區內容；不改寫歷史，之後不再合併 Core。

**產品參考**：Core 的 `docs/agent/**`，在 Agents 頁唯讀顯示，不屬於工作區。

## Agent 工作區

Agent 工作區是 Pi 工作的資料夾，由資料夾決定範圍。每個儲存庫的根目錄一定是 Agent 工作區；筆記本根目錄、它的上層，或筆記本內的資料夾放了 `AGENTS.md` 也成為工作區。Agents 頁與 Agent 窗格都以工作區為單位。

### 用語

**Agent 工作區**：一個儲存庫裡的資料夾，帶著自己的核心指示與技能；Pi 在其中執行時，也套用外層工作區的核心指示與技能。避免稱為：agent system、執行目錄。

**核心指示**：工作區資料夾的 `AGENTS.md`。避免稱為：工作區共用、系統指令、CLAUDE.md（Claude 專用副本）。

**skill（技能）**：`<工作區>/.agents/skills/<name>/` 裡以 `SKILL.md` 為入口的指令，附帶參考資料（`scripts/` 以外的 Markdown 或文字檔）與腳本（`scripts/` 內的文字檔），名稱等於資料夾名。避免稱為：`.claude/skills`（客戶端專用副本）。

**MCP 伺服器設定**：Pi 連線的 MCP 伺服器。可能帶 token，從不放進儲存庫；社群版在 Pi 裡設定，Pro 版存在伺服器的加密紀錄。

MCP 的 `get_system_prompt`、`list_skills` 與 `invoke_skill` 照舊從目標資料夾往上讀每一層的 `AGENTS.md` 與 `.agents/skills`。

## 工作區呈現

合輯是筆記本內一份像筆記的檔案 `<名稱>.compilation.yml`，把內容集合成可閱讀、可學習的整體。
合輯屬於路徑所在的筆記本，只收該筆記本的內容。
自訂合輯持有項目參照；動態合輯持有 tag 或 folder 查詢。
合輯有三種排列：河道（水平卡片，縮圖、小、中版型）、書本（左側目錄，項目依序鋪成區段並連續捲動）、關聯圖。
河道的卡片與書本的筆記區段都能就地編輯：點內文或「編輯」，卡片或區段就變成該筆記的編輯器，同一時間只有一處在編輯；點標題仍在放大檢視中開啟同一個編輯狀態。
編輯時維持閱讀時的版面：沒有分頁、紙面、工具列與底部狀態列，只多一行存檔狀態；原始碼模式、大綱與屬性到放大檢視使用。
合輯寬度不到 560px（分割的 Focus 窗格、手機）時，河道的卡片改為由上往下排成一欄，寬度跟著合輯，高度仍依縮圖、小、中而定。
學習用獨立按鈕進入學習頁；需要修改筆記時開啟原本編輯器。

合輯不擁有原始資料。
取消釘選或刪除合輯不刪除筆記、資料夾、資源。
動態內容不可拖入或拖出，只有自訂項目支援同一合輯內與跨合輯拖曳。

合輯檔隨筆記本內容一起放在 Git，跟著筆記搬移與同步；搬移或重新命名筆記與資料夾時，合輯內的參照一併更新。
舊版 `.github-notes-screen.yaml`（Screen Page）已由 `pnpm migrate-workspace` 轉成合輯檔並刪除。
本機草稿只是尚未儲存的恢復副本，不代表合輯已同步。

## 關聯圖與合輯（已確認方向，待實作）

### 用語

**合輯**：由自訂項目參照或動態查詢界定的內容集合，存成筆記本內的 `*.compilation.yml`，可以用不同排列顯示。避免稱為：Screen、泳道。

**河道**：合輯的一種排列，水平卡片列。不再指整個內容集合。

**書本**：合輯的一種排列，左側目錄加上整份合輯連續捲動的內文，項目依序成為章節，資料夾的筆記成為其下的小節，筆記區段可就地編輯。取代舊稱「拼接」與「堆疊」（檔案裡的舊值 `stack` 仍讀成書本）。避免稱為：拼接、堆疊。

**就地編輯**：在合輯的卡片或書本區段內直接編輯筆記，不離開合輯；用的是同一個筆記編輯器與同一份草稿，沒有另一條儲存路徑。

**關聯圖檢視**：由指定筆記集合及其內容連結形成的空間呈現。合輯可以作為它的內容範圍，也可以直接使用關聯圖排列。

**筆記節點**：筆記在關聯圖中的同一個物件，可以收合為節點或展開為可編輯筆記。展開不建立另一份筆記，多選與展開是不同操作。

使用者可將關聯圖內多選的筆記存成合輯，再由合輯開啟關聯圖。合輯持有筆記參照，正文與連結仍由原筆記擁有；移除合輯或收合節點不刪除原筆記。

## Focus 與 zoom（已確認方向，待實作）

Notes 的瀏覽區顯示篩選結果；Focus 顯示時，瀏覽區讓出空間停靠在旁，點選的筆記開進 Focus。zoom 是單一筆記的全螢幕編輯畫面，一般瀏覽時點選筆記就進入 zoom。

### 用語

**Focus**：屬於單一筆記本的一組窗格，依劃分排列，窗格內的 tab 參照該筆記本的筆記或河道。Focus 只持有參照，移除 tab 或刪除 Focus 不刪除內容。避免稱為：窗格模式、notes tiles、工作區。

**暫存**：每個筆記本唯一的未命名 Focus，用來隨手開啟筆記。命名後成為具名 Focus，暫存回到空白。英文介面稱 Scratch。避免稱為：(current)（程式內代稱，見 `CURRENT_FOCUS`）。

**劃分**：Focus 的窗格排列方式，固定為單一、左右、上下、左大右二、上大下二、三欄、2×2。避免稱為：版型（已指河道卡片大小）、layout。

**窗格**：劃分中的一格，持有一個以上的 tab，同時顯示其中一個。避免稱為：tile、面板（已指文件面板與右側工具）。

**作用窗格**：Focus 中接收開啟動作的窗格，同時只有一個。避免稱為：焦點格、目前格。

**tab**：窗格內對一則筆記或一條河道的參照。同一則筆記在一個 Focus 裡只有一個 tab。避免稱為：分頁（已指筆記的線性頁面）。

**zoom**：單一筆記的全螢幕編輯畫面，關閉後回到進入前的畫面。避免稱為：全屏 dialog、編輯器 modal。

**瀏覽區**：顯示 Notes 篩選結果的 list、flat、card、kanban 區域。Focus 顯示時，list、flat 停靠左側，card、kanban 停靠在 Focus 上方。避免稱為：筆記欄、notes list pane。

## 大綱筆記

**大綱筆記（Outline note）**是以 `*.outline.md` 副檔名辨識的 Markdown 筆記類型，介面簡稱「大綱／Outline」。
一個筆記本可以有多份各自具名的大綱，沿用一般筆記的身分、前置資料、編輯器、草稿與儲存流程。
**項目／節點**是一般清單項目，可包含文字、零個或多個連結、註記及任意層子項目。
**註記**是同一項目內沒有新清單標記的延續文字。
文字項目不代表資料夾，含連結的項目也可以有子項目。
書籤清單只是大綱的一種用途。

Enter 新增同層項目，Shift+Enter 新增同項註記，Tab／Shift+Tab 縮排或提升整個子樹；即時編輯器支援同份大綱內拖曳及單次復原。
所有操作修改同一份 Markdown，不另存可編輯樹狀資料或節點 ID。
「加入大綱」先選擇既有或新建的大綱，再於實際開啟的編輯器插入目前內容的普通連結。
內部連結與搬移以筆記本及儲存庫為範圍；不同儲存庫的相同路徑不是同一目標。
本機儲存、遠端瀏覽器草稿及 Git 提交維持不同狀態。

**舊書籤集合**指保留於 `.mygitnotes-bookmarks.yaml` 的相容資料，已退出一般編輯與變更流程。
顯式匯入可將筆記、合輯與 HTTP(S) 連結轉成新大綱，群組轉為文字父項目；精確位置、查詢與資料夾保留於來源並列出原因。
部分匯入必須確認，永不覆寫或刪除原始來源，也不重新指派未知擁有者。
瀏覽器舊草稿以完整原始資料匯出或明確捨棄，保留原基底與版本，不自動合併或儲存。
舊檔案的保護與受控搬移參照更新仍保留。

## 分頁與學習

正文頂層 `---` 將筆記分為線性頁面。一般閱讀仍以分隔線呈現；分頁閱讀依原始順序翻頁。學習卡以頁面對應定義題目與答案，每張卡有固定身分與獨立記憶排程。一份筆記可對應多張卡；反向卡與填空卡共用原始內容。

閱讀與回想事件分開記錄。學習流程以 note status 定義階段，熟悉程度控制前進或退回，複習間隔由目的階段決定。階段與間隔由學習頁的合輯編輯視窗配置；一般合輯保留原本操作。合輯引用同一份學習資料，移除項目保留學習紀錄。每個筆記本儲存庫根目錄的 `.github-notes-study.yaml` 保存該儲存庫內筆記本的卡片身分、階段、到期及事件，透過 Git 跨裝置同步。

閱讀／學習頁一次顯示一張卡片，題目及答案揭示後可來回翻頁，切卡不寫入評分。`/notes/study?notebook=<id>&path=<路徑>` 是合輯的專屬全螢幕學習頁，開啟時切換到合輯所屬筆記本，固定最早到期排序，保留操作與編輯器返回來源，與合輯排列分開。舊網址 `/screen/lanes/<id>` 會轉址到對應合輯的學習頁。學習紀錄以合輯的 `id` 為鍵，遷移後歷史不變。

上次移動時間是使用者最近一次成功提交熟悉程度的時間；忘記、吃力、記得、輕鬆皆算移動，保留原階段也重新計時。到期由該次移動時間加目的階段間隔決定。自訂延後調整到期，保留上次移動時間；撤銷還原前次時間。翻頁、切卡與略過屬於閱讀操作。
